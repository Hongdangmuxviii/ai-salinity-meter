# AI 염도계 안드로이드 앱 (기능 우선 v0.2)

[펌웨어 SalinityMeterApp](../firmware/SalinityMeterApp/README.md)과 BLE로 연결하는 앱입니다. 특허명세서 P2026-070의 S100~S700 흐름을 따릅니다.

1. 기기에서 염도, ToF 깊이맵, 사진을 받습니다.
2. **카메라와 ToF로 국물 부피(Vbroth)**를 추정합니다.
3. 이 부피로 소금 g 또는 물 mL를 안내합니다.

부피 정확도를 높이기 위해 네 가지 방법(A~D)을 함께 씁니다. 디자인은 나중에 하고, 지금은 Material3 기본 컴포넌트로 기능만 구성했습니다.

> **상태 (2026-11-24): 빌드·단위 테스트 33개·Lint 통과, 실기기 실행 전.** 디버그 APK는 약 26MB(arm64 전용)입니다. 계산은 합성 데이터와 특허 예시로만 검증했고, 실제 음식·용기·센서로는 아직 검증하지 않았습니다.

## 화면 (탭)
| 탭 | 기능 |
|---|---|
| 연결 | 권한 요청 → `SaltMeter-XXXX` 검색·연결 → 기기 센서 감지 상태 표시 |
| 측정 | 염도 측정, 스캔(ToF+사진), 현재 염도, 가이드, 부피 계산 중간값, 사진 위 건더기 영역 표시, 사진 전송 속도(KB/s) |
| **조리** | 음식 이름 → **A 용기 학습** → **B 건더기 투입 기록** → **부피 결정(A~D 융합, C 깊이 모델)** → **간 맞추기(나눠 넣기 + 역산)** |
| 설정 | 용기 치수(학습 전 기본값), 바닥 기준거리, 건더기 보정 방식·γ·ΔE, 사진 속 용기 원, 카메라–ToF 정합, 사진 해상도, K |
| 로그 | 주고받은 JSON 원문, 직접 명령 입력 |

## 부피를 구하는 네 가지 방법

### A. 용기 학습: ToF로 A(h) 측정 (특허 ¶72)
1. 빈 용기를 센서 아래 둡니다. 바닥까지 거리(Dfloor)를 잽니다.
2. 계량한 물을 여러 번 나눠 붓습니다(예: 100mL씩). 부을 때마다 ToF로 수면 높이를 잽니다.
3. (높이, 누적 부피) 점들을 이어 V(h)를 만듭니다. 마지막 점보다 높은 수면은 마지막 구간의 단면적을 연장해서 계산합니다. → `Container.Calibrated`
4. 용기 이름으로 저장해 두고 골라 씁니다. 저장된 용기에는 바닥 거리도 함께 들어 있습니다.

효과: 치수 입력이나 원뿔대 가정에서 생기는 오차가 없어집니다. 사진 없이 할 때는 수면 거리를 ToF 중앙 4×4칸의 중앙값으로 잡습니다. 바깥 칸은 그릇 테두리나 식탁을 볼 수 있기 때문입니다.

### B. 건더기 투입 변위 (넣기 전·후 ToF)
- 건더기를 넣기 직전과 직후에 수면 높이를 잽니다. `V(h후) − V(h전)`을 건더기 부피로 장부에 쌓습니다. → `DisplacementLedger`
- **카메라가 볼 수 없는 잠긴 건더기까지** 잡힙니다.
- 처음 넣기 전의 부피는 "조리 전 물 양"으로 기록합니다.
- "넣은 후" 측정에서는 사진도 함께 찍습니다. 수면 높이는 건더기가 없는 ToF 칸으로만 잡고, 건더기 면적비 α도 같이 기록합니다.
- 한계: 끓이는 동안의 증발과 면의 흡수는 반영되지 않습니다. 이 부분은 D가 보정합니다.

### C. 깊이 지도 융합 (카메라 단안 깊이 + ToF 실제 거리)
1. 사진을 깊이 추정 모델(ONNX)에 넣어 상대 역깊이 지도를 얻습니다. → `DepthEstimator`
2. ToF 칸마다 그 영역의 모델 값 평균 rᵢ와 실측 거리 dᵢ로 `1/d = s·r + t`를 최소제곱 피팅합니다. 이상치는 한 번 걸러낸 뒤 다시 맞춥니다. → `DepthFusion.fit`
3. 건더기 픽셀마다 `(수면 거리 − 픽셀 거리) × 픽셀 바닥면적`을 더해 수면 위 부피를 구합니다. 여기에 γ돌출을 곱합니다.

- 효과: ToF 8×8칸(한 칸 15~20mm)보다 훨씬 촘촘하게 돌출 부피를 잽니다.
- **모델 파일은 APK에 들어 있지 않습니다.** 조리 탭의 "깊이 모델(.onnx) 가져오기"로 넣습니다.
- 모델이 없으면 8×8 ToF 돌출식과 면적식으로 대체합니다.

### D. 염도 역산 + 융합 + 학습
- **역산**: 투입 전후 염도로 국물량을 구합니다.
  - 소금을 넣었을 때: `V = W / (K·ΔS)`
  - 물을 넣었을 때: `V전 = ΔV·S2/(S1−S2)`
  - 측정 잡음(약 ±0.02%p)으로 오차 범위도 같이 계산하고, 염도 변화가 잡음의 3배보다 작으면 역산하지 않습니다. → `BackCalc`
- **융합**: 카메라+ToF 추정치와 역산값을 각자의 불확실성으로 가중 평균합니다(역분산 가중). → `Fusion`
- **학습**: 음식 이름별로 `역산값 / 보정 전 카메라+ToF 추정치` 비율을 누적해 다음 조리에 곱해 줍니다. → `FoodCorrection`
  - 이 비율에는 γ, 흡수, 증발, 정합 오차가 한꺼번에 담깁니다.
  - 3회 이상 쌓이면 추정 불확실성도 줄여서 계산합니다.
- **나눠 넣기**: 역산값이 아직 없을 때는 첫 투입량을 `1 − 1.5×(추정 상대오차)` 비율로 줄여 안내합니다(50~100% 범위). 역산값이 생긴 뒤에는 남은 양을 전부 안내합니다.

### 최종 국물량 결정 (`VolumePlanner`)
1. 전체 부피: A로 학습한 용기가 있으면 그것을, 없으면 설정 탭 치수를 씁니다.
2. 건더기 부피: **B(투입 변위) → C(깊이 지도) → 면적식과 8×8 돌출식 중 큰 값** 순서로 있는 것을 씁니다.
3. `카메라+ToF 추정 = (Vtotal − Vsolid) × 학습 보정`을 계산하고, 역산값이 있으면 융합합니다.
4. 소금 `(St−Sc)·V·K`, 물 `V·(Sc/St−1)`을 계산합니다(특허 수학식 1·2). 완료 판정은 ±0.05%p입니다.
5. 결과는 펌웨어 `broth <mL> <비율>` 명령으로 기기 OLED 가이드에도 반영합니다.

## 조리 탭 사용 순서
1. 음식 이름을 입력합니다(학습 단위). 처음이면 "새 조리 시작"을 누릅니다.
2. (처음 한 번) 빈 용기로 **용기 학습**을 합니다: 물을 붓고 측정하기를 반복한 뒤 저장합니다.
3. 물을 담고 **① 건더기 넣기 전 측정**을 누릅니다. 조리 전 물 양이 기록됩니다.
4. 건더기를 넣고 **② 넣은 후 측정**을 누릅니다. ToF와 사진으로 변위가 기록됩니다. 건더기를 넣을 때마다 반복합니다.
5. 측정 탭에서 염도를 잽니다. 조리 탭에 **지금 넣을 양**이 나옵니다.
6. 넣고 저은 뒤, 실제로 넣은 양을 입력하고 **넣고 저음 → 재측정**을 누릅니다. 역산 → 융합 → 남은 양 안내 순서로 진행되고, 학습 기록도 쌓입니다.
7. 목표 ±0.05%p 안에 들어오면 끝입니다. 3회를 넘기면 수동 조정을 권장합니다.

## 아직 실험으로 정해야 하는 값
- γ면적 0.5, γ돌출 2.0: 임시값입니다. D 학습 비율이 결과적으로 이 오차를 흡수하지만, 첫 조리에서는 부정확합니다.
- ΔE 18과 반사광 기준: 실제 국 사진으로 조정해야 합니다.
- 카메라 화각 55°×42°, ToF 방향(회전·반전): 조립 후 확인해야 합니다. C의 피팅 오차(mm)가 화면에 표시되니 정합이 맞는지 판단하는 데 쓸 수 있습니다.
- 추정 불확실성 수치(용기 5/12%, 건더기 25~60%): 경험적으로 정한 값입니다. 실측 데이터가 쌓이면 다시 맞춰야 합니다.
- ToF가 물 표면에서 안정적으로 읽히는지: 실물로 확인해야 합니다. 맑은 물은 적외선이 거울처럼 반사되어 유효 칸이 줄 수 있습니다.

| `ui` | 탭 화면 5개 |

단위 테스트(33개)에서 확인하는 것:
- 특허 예시: 2.4g, 200mL
- 용기 학습으로 원통 부피 재현
- 변위 계산
- **합성 장면에서 깊이 지도 스케일 맞춤 오차 1mm 미만, 돌출 부피 ±10%**
- 소금·물 역산(800mL, 1000mL)
- 융합 가중치, 학습 비율, 플래너 우선순위와 나눠 넣기 비율
